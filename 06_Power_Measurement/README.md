# Power measurement entry point

Power is a physical experiment and is not generated by the host reconstruction
pipeline. Complete the software, RTL, Vivado, package, board-function, and
board-accuracy gates before collecting formal power data.

## PC GPU

From this directory in the `nerf2` environment, run:

```text
python run_pc_all_scenes.py
```

Each scene uses every ID in its test split and runs three independent repeats.
The `nvidia-smi` signal covers the NVIDIA discrete-GPU power domain. It does not
represent wall power for the whole computer.

## PYNQ FPGA and ARM

The generated board package includes:

```text
jupyter/stage39_fpga_fulltest_power.py
jupyter/stage39_arm_fullmap_benchmark.py
jupyter/stage39_power_clock.py
```

Run every scene three times on FPGA and three times on ARM. Each program JSON is
paired with an independent FNB58 raw record. Use
[BOARD_POWER_COMMANDS.md](BOARD_POWER_COMMANDS.md) for the commands and
[POWER_PROTOCOL.md](POWER_PROTOCOL.md) for the measurement boundary and
acceptance rules.

## Aggregation

The supplied tools convert meter logs, audit time alignment, summarize board
runs, summarize the PC runs, and build a boundary-aware comparison:

```text
convert_usbmeter_cfn.py
audit_board_power_capture.py
summarize_board_power.py
summarize_pc_full_test.py
summarize_comparison.py
```

Do not reuse power results from another bitstream, runtime model, board package,
or reproduction run.
